Internal Storage

-   MySQL: InnoDB, Row storage, B+ Tree indexes
-   MongoDB: WiredTiger, BSON documents, B+ Tree indexes
-   Cassandra: LSM Tree, SSTables, Bloom Filters, Partition Index

Strengths

MySQL

-   ACID transactions
-   SQL
-   Complex joins
-   Mature optimizer

MongoDB

-   Flexible schema
-   Rich indexing
-   Easy object mapping

Cassandra

-   Massive horizontal scaling
-   Millions of writes/sec
-   Excellent key-value lookups
-   No master bottleneck

Weaknesses

MySQL

-   Hard to shard
-   Write scaling is difficult

MongoDB

-   Limited joins
-   Multi-document transactions are expensive

Cassandra

-   No joins
-   Query-driven schema design
-   Secondary indexes don’t scale well

When to Choose

-   Banking, Orders → MySQL
-   User Profiles, Product Catalog → MongoDB
-   TinyURL, WhatsApp Messages, Metrics, IoT → Cassandra

Interview Rule

-   Need joins + transactions + SQL → MySQL
-   Need flexible JSON documents → MongoDB
-   Need billions of rows + millions of writes/sec + PK lookups →
    Cassandra
